# Agent Instructions

- This is a NixOS flake using Den’s dendritic layout. `flake.nix` uses `import-tree` to auto-import `modules/`, which holds framework, schema, host, and quirk plumbing. `aspects/` is the canonical home for configuration aspects. Inspect the existing layout before suggesting where configuration belongs, and never edit generated files such as `flake.lock` or `devenv.lock` by hand.
- Aspect discovery is implemented by `modules/aspects.nix`, not Den itself: it scans `aspects/` during evaluation and registers each file or directory as `den.aspects.<path>`. A name may be a file or a directory, not both. A directory with `default.nix` uses that file as its aspect; a directory without one becomes an aspect that includes all of its subaspects.
- The aspects framework is effectively final. Future framework changes should normally only add utilities to the generated `aspect-utils` interface; do not redesign the aspect import/discovery mechanism without a concrete requirement. Directory aspects can use `aspect-utils.includes-all-subaspects`, `includes-all-subaspects-except`, and `self` for hierarchical composition, and any aspect can fan out to every user of a host with `provides.to-users`.
- The agent's role in this repository is analysis-only: explain the flake, trace configuration behavior, identify risks, and propose changes. Do not write code or Nix configuration, create patches, or commit changes unless the user explicitly requests a repository documentation or configuration change.
- `flake.nix` is hand-written (it was previously generated by `flake-file`). Edit it directly and update `flake.lock` with `nix flake update` or `nix flake lock`; the `nix run .#write-flake`, `write-inputs`, and `write-lock` commands no longer exist.
- Host definitions are in `modules/hosts.nix`: `archer` and `hierophant`. A host's aspect defaults to `den.aspects.<host>`, so its hardware and host-specific settings belong in `aspects/<host>.nix` and the filename must match the host key. Shared host-level includes are configured in `modules/schemas/host.nix`, and shared defaults in `modules/defaults.nix`.
- Impermanence lives in `aspects/impermanence/`: `default.nix` imports the impermanence modules, makes `/persistent` needed for boot, declares the base system and home persistence paths, and aggregates `persist` declarations from included aspects; `diff.nix` adds the `impermanence-diff` and `impermanence-home-diff` helpers for finding files not preserved across reboots. The initrd deletes and recreates the Btrfs `root` subvolume on every boot (using `/dev/disk/by-label/nixos`), so anything not declared persistent is intentionally ephemeral.
- `persist` is a Den quirk registered in `modules/quirks.nix`, not a normal NixOS option or separate aspect. Use `persist.directories`, `persist.files`, `persist.home.directories`, and `persist.home.files` in aspects; the impermanence aspect aggregates these into system and Home Manager persistence. Be careful with paths and directory attribute sets because they directly control what survives the root rollback. `caddy-configs` is the other registered quirk; service aspects use it to contribute Caddy virtual hosts.
- Validate changes with `nix flake check --no-build --no-write-lock-file`; at the current revision it passes and evaluates `nixosConfigurations.archer` and `nixosConfigurations.hierophant`. The flake exposes no custom `checks`, `apps`, or `packages`, so this evaluation is the focused verification step; use `nix build .#nixosConfigurations.<host>.config.system.build.toplevel` for a full build.
- Secret material must be encrypted with `git-crypt` before it is stored in the repository. Encrypted `git-crypt` ciphertext may also be stored in the Nix store because this is currently a single-machine setup. Never decrypt, print, replace, or expose secret contents. Secret paths include `*.secret`, `*.secret.*`, and files below `*.secret/`, as matched by `.gitattributes`.
- No CI, pre-commit hooks, or automated format/lint/test checks are configured. `devenv.nix` provides a development shell with `alejandra`, `stylua`, `lua-language-server`, and `fish-lsp`, but formatting and linting are not enforced.
