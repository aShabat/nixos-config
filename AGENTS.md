# Agent Instructions

- This is a NixOS flake using Den’s dendritic layout. `modules/` is auto-imported by `flake.nix`; it contains framework, schema, host, and quirk plumbing. `aspects/` is the canonical home for configuration aspects. Inspect the existing layout before suggesting where configuration belongs, and never edit generated outputs.
- The aspects framework is effectively final. Future framework changes should normally only add utilities to the generated `aspect-utils` interface; do not redesign the aspect import/discovery mechanism without a concrete requirement. Aspect directories and files are auto-discovered, and directory aspects can use `aspect-utils.includes-all-subaspects`, `includes-all-subaspects-except`, and `self` when they need hierarchical composition.
- The agent's role in this repository is analysis-only: explain the flake, trace configuration behavior, identify risks, and propose changes. Do not write code or Nix configuration, create patches, or commit changes unless the user explicitly requests a repository documentation or configuration change.
- `flake.nix` is generated by `flake-file`. Do not edit it manually; regenerate it with `nix run .#write-flake`. Related generated-input and lockfile commands are `nix run .#write-inputs` and `nix run .#write-lock`.
- Host definitions are in `modules/hosts.nix`: `archer`, `hierophant`, and `scribe`. Their hardware and host-specific settings are in the matching top-level module files.
- Impermanence is implemented by `aspects/impermanence.nix`. It imports the impermanence modules, makes `/persistent` needed for boot, declares the base system and home persistence paths, and collects persistence declarations from included aspects. The initrd deletes and recreates the Btrfs `root` subvolume on every boot, so anything not declared persistent is intentionally ephemeral.
- `persist` is a Den quirk registered in `modules/quirks.nix`, not a normal NixOS option or a separate aspect. Use `persist.directories`, `persist.files`, `persist.home.directories`, and `persist.home.files` in aspects to contribute paths; the impermanence aspect aggregates these values into system and Home Manager persistence. Be careful with paths and directory attribute sets because they directly control what survives the root rollback.
- Validate changes with `nix flake check --no-build --no-write-lock-file`. The current baseline fails while evaluating `scribe` because `services.netbird.domain` is unsupported by the locked NetBird module; distinguish this pre-existing failure from regressions.
- The flake also exposes the `check-flake-file` check and NixOS configurations under `nixosConfigurations.<host>`.
- Secret material must be encrypted with `git-crypt` before it is stored in the repository. Encrypted `git-crypt` ciphertext may also be stored in the Nix store because this is currently a single-machine setup. Never decrypt, print, replace, or expose secret contents. Secret paths include `*.secret`, `*.secret.*`, and files below `*.secret/`, as matched by `.gitattributes`.
- No repository CI, formatter, linter, or application test runner is configured; use Nix flake evaluation as the focused verification step.
